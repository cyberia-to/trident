Next after Noun; feature PRs into release/0.4. Preserve primitive program ART1 identities and the raw/structured entry ABIs. Current native compiler needs Digest identity, tuple return types/values, destructuring declarations and tuple assignment for validation-budget threading. Real imports/nominal structs/arrays still follow; these deliveries must not claim full SH3.

## Canonical descriptors first
Represent types as canonical Noun values, with current primitive tags remaining atoms. Primitive AST/signature/binding records therefore preserve their bytes. Composite descriptors carry kind, ordered children, derived logical depth and contains_noun. Equality uses native identity of canonical descriptors; primitive tests compare with explicit tag atoms. No mutable type interner or O(n²) search, no evolving registry through every body.

Move type ownership into types.tri; migrate AST type access, signatures, bindings, body result and builtins from Field to Noun. Primitive tags have one owner in types.tri; packed records insert complete descriptors without atom wrapping. Primitive construction/equality uses direct noun intrinsics so the guest compiler avoids an extra function invocation per check. Invalid type has a unique descriptor distinct from all valid primitives/composites. Keep token recognition and all current accepted syntax unchanged in the initial refactor. Component tests assert primitive record byte preservation, exact descriptor equality and bounded composite construction. Full old JOB/ART1 corpus must preserve outputs/identities. Formally audited UNKNOWN is still not proof.

Composite constructors use bounded child sequences and explicit logical nesting/node limits derived from job capacity and parser STACK_CAP. Derived depth/contains_noun must come from trusted child descriptors; never accept caller-supplied metadata. Nominal struct identity later includes the defining module, not structural equivalence. Fixed arrays later carry element type and checked extent. Type bounds, output formula depth and execution arena remain independent.

## Digest and tuple language increments
Digest is its own primitive descriptor. nox_noun_identity evaluates its Noun argument once, then axis0 returns native balanced [[a b][c d]]. It never reuses tuple cons-list layout. Equality/type checks and any admitted Digest indexing match the seed; direct identity is needed before qualified imports. Structurally compare full 4-word output against independently loaded input particle, not a scalar projection.

Seed tuple syntax is unusual: `(T)` is a singleton tuple type; `()` and trailing comma in type are rejected. `(x)` groups an expression; values require at least two items, `(x,)` and `()` reject, `(x,y,)` accepts. Source contract must preserve these distinctions. Type/value parser continuations are bounded and own their child lists; comma must distinguish tuple context from function argument context. Each tuple is a cons-list of complete component values, ending in zero; Unit components retain their zero leaf and Noun components retain entire subtrees.

Destructuring evaluates RHS once into a hidden slot before any binding/write. New let names are installed only afterward. Assignment `(a,b)=(b,a)` reads both old values before ordered writes. `_` is admitted only in let patterns. Repeated names follow seed final-binding/ordered-write behavior. Check every target's type/mutability/arity before code emission; nested destructuring is unsupported unless seed syntax admits it. Tuple equality requires same descriptors and contains_noun=false, including nested components; Noun-containing tuples use explicit projections/native operations. Physical flat width is separate from native subtree slots.
