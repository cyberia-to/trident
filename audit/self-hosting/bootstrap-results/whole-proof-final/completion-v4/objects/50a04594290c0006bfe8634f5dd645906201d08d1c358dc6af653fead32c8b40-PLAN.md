# Exact duplicate C1 prefix reclamation proposal

Scope is one failed C1 cost temporary at
`whole-proof-attacks-v3-c1/whole-c1/certificate-cost.joysc`, 11901028947 bytes,
SHA-256 `a4108874af7f843bb86e89442c5ca4071a638d45c3d24b8aa7f20fa1f96b95ed`.
The original read-only observation compared every byte to range `[0,11901028947)`
of immutable C1 proof `80212be832ce0a5caafa69d9dd346ff20d51ce20fc86892f0c7039492619bbb0`
(11977015727 bytes). It also hashed the entire original and recorded stable
single-link device/inode/mode/size/mtime/ctime/birth identities before and after.

Preparation copies original coordinator failure, cleanup error, cost timeout,
command logs, native registrations, later independent quiescence observation,
prefix comparison and first/last samples. Complete original process snapshots
stay local with only their path, length and digest in the public manifest.
Read-only preparation also hashes the C2 original, both older partials and C2
complete cost mutant to bind their continued preservation. No proof status,
original receipt, production source or existing runtime allowance changes.

The real action is disabled until a separate `review.json` with status
`passed-prefix-reclamation-source-review` binds exact `sources.json` and
`plan.json` identities, and its SHA-256 is explicitly supplied to `reclaim.py`.
Only a new `action-1` and `private-action-1` are allowed. No retry, automatic
cleanup or automatic reconstruction is implemented. Preparation releases zero
bytes; all previously held bytes remain charged until the actual transition.

The action acquires every existing v1/v2/v3 suite/coordinator lease and the v3
accounting lease without writing them. All ancestor components and final files
are opened without following symlinks; data files must be regular single-link
files matching the exact stable recorded state. Original and duplicate file
descriptors remain held throughout the transition. The lock and directory
identity guards assume the existing cooperative lease protocol; this is an
owned-workspace operation, not a defense against a privileged hostile actor.

Two fresh complete process inventories check all original PID/PGID/parent IDs.
The second starts at least two seconds after the first, after all complete
pre-action scans. A matching process is accepted as unrelated PID reuse only
when its actual UTC birth is strictly later than the retained historical empty
observation plus two seconds. Older, ambiguous or malformed observations fail.
No signals are sent. The exact registration set and original failures are
checked again before the transition. Raw host inventories stay in the private
directory; public receipts contain identities and relevant reused IDs only.

Before unlink, the driver repeats full prefix byte equality and both hashes,
authenticates the entire original, checks all untouched protected files, and
durably writes `before-unlink.json`. It rechecks every held identity after that
fsynced receipt, then unlinks only the pinned C1 name through its held parent
descriptor. The immediate fsynced `after-unlink.json` still charges the complete
prefix because its descriptor remains open. A second full equality/whole hash
scan reads that same unlinked inode, rechecks all protected files and original
failure evidence, and writes `verified-held.json`. Only after every descriptor
closes and the name remains absent can `final.json` release this one logical
scope charge. No physical free-space delta is inferred. Any failure retains an
explicit immutable failure receipt with actual unlink state and conservatively
keeps the logical charge; no historical status is replaced.

The transition has a 600-second read/metadata allowance and 1 MiB scan chunks.
It changes none of the proof/helper CPU, wall, RSS, wire or shared-disk bounds.
The immutable source and plan identities, exact original failures and durable
pre/post records make a process interruption diagnosable even between unlink
and terminal receipt; action directories are never overwritten.
Every action journal also records its exact review, source inventory, plan,
individual source-file identities and command. Those bindings are rechecked
before both pre-transition observations complete and after the post-unlink scan.

`reconstruct.py` is a separate explicit future command. It authenticates the
entire original before creating an exclusive fresh `reconstructed-*` file,
copies exactly the recorded prefix, hashes the output, rehashes the whole
original and performs output readback. Admission requires output length plus
the unchanged 8 GiB free floor. Existing destinations and protected paths are
rejected; interrupted new outputs remain as evidence. Reclamation never calls
this command, and reconstruction is not a negative-proof acceptance result.

Validation uses isolated tiny synthetic files under this proposal directory.
It exercises the exact transition including unlink only for those disposable
test fixtures, strict inode/link/type/path guards, changed bytes and journal
race rejection, protected file changes, interrupted post-unlink accounting,
birth/PID reuse classification, failure-evidence integrity, leases, durable
non-overwrite behavior, and deterministic reconstruction. No real C1 unlink
or real reconstruction is executed during preparation or tests.
